## Final runtime and safety evidence

The exact installed artifact passed [all 31 live matrix checks](evidence/live-matrix-results.json) with zero failures. Four serial owned profiles cover YAML + CronJob/PVC/init logs, local Helm, contained Kustomize, and a trusted prebuilt image with a deliberately failing process. Actual Docker pause/reconnect, interrupted installed UI/reset recovery, reset/apply overlap refusal, data/Job-preserving reset, constrained repairs and repeated cleanup passed. [Kustomize provenance](evidence/kustomize-version-proof.json) is bounded and the actual deployment is healthy. The [historical matrix](evidence/matrix-before-kustomize-fix.json) had 24 passes and one Kustomize import failure; that failure is now resolved by the final installed rerun.

One overlapping core test-harness run was invalidated when a second runner changed the canonical test source. Both were stopped, the validated owned lab was cleaned up, and the full isolated core journey passed. This failed harness run is not counted as product proof. The matrix restart helper also lost its child UI when its executor exited after completing all checks. Restarting the exact installed CLI confirmed the [persisted stopped journal](evidence/final-stopped-journal.json). The [child-detachment follow-up](evidence/harness-detachment-proof.json) passes an actual, no-secret process-group exit/survival/shutdown check. It affects test orchestration only, not the frozen product artifact; the matrix was not rerun for that test-only change.

[Final environment comparison](evidence/environment-preservation.json) proves normal kubeconfig bytes/context and all 12 baseline container identities remain unchanged, including the separate hello-world cluster; no Waypoint driver containers remain. [Final UI shutdown](evidence/final-ui-shutdown.json) stopped only the verified installed test CLI. No source-cluster API requests were made. [Independent review](reviewer-resolutions.md) covers code, package, UI, core and matrix; author inspection is not counted as independent review.

The real matrix uses one namespace per fixture and same-server operation overlap. Namespace rewriting and two-process kernel lock contention have focused tests; a real multi-namespace deployment or two separate CLI runtime mutations are not claimed. Actual failed deployment is an expected negative case, not a passing-health substitution.

## Supported boundaries and unrun external checks

- NetworkPolicy execution is refused without an evidenced enforcing CNI. HPA execution is refused without metrics and dynamic-replica semantics. Tests prove the gates; their unsupported execution is **NOT RUN**.
- Hooks/CRDs/operators, remote Kustomize/plugins/embedded Helm and unsupported Argo options are diagnosed/refused, not silently removed. GPU/cloud/storage/affinity/capacity prerequisites require explicit configuration/provisioning.
- Actual private-registry/private-repository authentication and live optional Vault installation are **NOT RUN**. No production credentials or new persistent grants were supplied. Public images/local trusted images and explicitly authenticated local rendered inputs are alternatives. No private integration health is claimed.
- Kubernetes 410/expired-history, malformed stream frames, provider auth/quota/timeouts/cancellation and late response ordering use controlled regressions. Real disconnect/restart evidence is recorded separately.
- CI/release checks are prepared in `.github/workflows/verify.yml`; external CI is **NOT RUN**. No workflow, image build, publication or visibility change has been triggered.
- The corpus does not justify compatibility with most repositories. Reset reapplies configuration; it does not recreate completed Jobs or erase PVC data.
- Removed legacy catalog/debrief components had no current callers. Legacy modeled checkpoint parsing/storage tests remain for compatibility and are not evidence of real practice.
